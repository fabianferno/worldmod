ETHOnline submission video — production plan

The threshold you have to clear is invisible — including to us.

World Mod pays people in USDC to record real physical tasks on a head-mounted phone, scores the footage from the actual bytes instead of trusting anyone's word, and — the part worth a video — moves the buyer's pass/fail bar into a Chainlink CRE enclave so the platform operator can no longer read it either.

Target length: 3:15 Primary track: Chainlink — Best Confidential Workflow Supporting evidence: Hedera ATS · World ID Selfie Check Prepared: Sept 2026

02 The story

Phases 2 & 4 — problem, insight, and the two things a judge should remember.

Problem
Embodied-AI and robotics models need first-person video of real hands doing real tasks. That footage barely exists at any scale, and 2026's funding wave (Physical Intelligence's $600M raise, humanoid teleoperation labs everywhere) is all bottlenecked on getting more of it.
User
Anyone with a phone and fifteen seconds — the same person Hivemapper or DIMO already pay to point a sensor at the world, just pointed at their own hands instead of the road.
Existing workflow
Either an institution flies out Meta Aria glasses to a few hundred people (Ego4D/EgoExo4D — real, valuable, ~88–3,670 hours total, hardware nobody can buy), or a gig platform like Scale AI/Surge AI pays contractors to label data through an opaque backend.
Their limitation
Institutional collection doesn't scale past a few hundred contributors. The gig-platform model scales, but Surge AI is being sued right now for wage theft and worker misclassification — and the actual, specific failure is an opaque ledger: workers get deactivated with no explanation and no appeal, across every platform the same company owns.
Our insight
The DePIN-for-physical-data model already works at real scale (Hivemapper: $18M revenue; DIMO: 180k vehicles) for data that's easy to verify (GPS trivially proves you drove somewhere). Nobody's pointed that model at data where "did a human genuinely do this" is the hard part — because verifying that requires a validator, and a validator is exactly where Surge AI's opacity problem re-appears. So we removed it twice: the accept/reject decision is measured from re-decoded bytes, not asserted; and the buyer's pass bar lives inside a Chainlink CRE TEE, invisible even to us.
Why Web3
Not because "blockchain." Because the actual bug in the Web2 version of this idea is a trusted middleman who can quietly move the goalposts or freeze an account with no audit trail. Escrow + on-chain payment release + a TEE-attested validator remove that middleman in a way a judge can check on Etherscan, not just trust.
Why now
Chainlink CRE Confidential Workflows and World ID Selfie Check both went beta this cycle. The demand curve for this exact data type is the steepest it's ever been.
Strongest differentiator: the bar you have to clear to get paid is gone from the API, gone from the page, gone from your rejection reason — on purpose, in code — and compared against your score somewhere no one, including us, can read it.

"Holy shit" moment: pull up the live bounty API in a browser tab — no threshold field. Cut to a real terminal running cre workflow simulate — the enclave rejecting a real episode with zero on-chain call. Then lower the secret by one line in .env, re-run the same episode, and watch the verdict flip and a real ValidationRecorded event land on the same deployed Sepolia contract. Same code, same episode, different secret, different on-chain outcome — visible, not asserted.

03 Who else does this — for real

Phase 3 — four real products, not invented competitors. Two prove the economic model works; one shows what happens without an honest validator; one shows what the underlying data is worth right now.

Hivemapper

DePIN precedent — proves the model
What it does
Pays drivers HONEY tokens to capture 4K dashcam imagery; developers burn tokens to consume the map data.
Real usage
33% of the global road network mapped; $18M revenue (Jan 2026); customers include Lyft, TomTom, Trimble.
Limitation
Authenticity is easy here — GPS + accelerometer trivially proves you drove somewhere. Doesn't need a validator.
depinscan.io/projects/hivemapper ↗

DIMO

DePIN precedent — proves the marketplace
What it does
Vehicle owners connect a device, share telemetry, and sell it in a token-settled marketplace to automakers/insurers.
Real usage
180,000+ vehicles connected; drivers saw $1,250 average annualized rewards (2023).
Limitation
Same as Hivemapper — vehicle telemetry is self-verifying. A different kind of physical data, one that doesn't have to solve "prove a human did this."
gate.com — DIMO explained ↗

Ego4D / Ego-Exo4D

The data type — proves the demand
What it does
Meta-led academic consortium collecting egocentric video with Project Aria glasses for embodied-AI research.
Real usage
Ego4D: 3,670 hours, 923 participants, 74 locations. Ego-Exo4D: ~88 hours, Aria + GoPro rigs.
Limitation
Hardware isn't commercially available; institutional, slow, and small relative to what training embodied AI actually needs.
ai.meta.com — Ego-Exo4D ↗

Surge AI / DataAnnotation

The failure mode — proves why trust matters
What it does
Gig platform paying contractors to label/generate AI training data through a centralized backend.
Reality (2025–26)
Class-action lawsuit over worker misclassification and unpaid wages; workers report accounts deactivated with no explanation and no path to reapply, blacklisted across every platform the parent company owns.
How we differ
Acceptance is measured from re-verified bytes and attested in a TEE — not a backend decision anyone can quietly make or unmake.

04 Opening hooks

Phase 5 — three options, pick one. Recommendation: Hook C, because the technical claim is the actual differentiator and it's provable on-screen in under ten seconds.

Hook A — Product-first

Open mid-recording: phone strapped to a head, live skeleton overlay, "Contribute an episode" — cut to the payout screen ticking up in real USDC. Fast, concrete, but doesn't signal the technical story.

Hook B — Real-world-first

Open on the Surge AI lawsuit headline on screen. "This is what happens when the company grading your work can also just... not tell you why it failed you." Strong emotional frame, costs 10–15s of setup before the product appears.

Hook C — Technical-wow-firstRecommended

Open on a real browser network tab hitting GET /api/bounties/bounty_keyboard_001 — no min_framing, no min_plausibility field. "This is the bar you have to clear to get paid. It's not in here. It's not anywhere I can read." Immediate, specific, and it's the actual thing that makes this project different — not a mood, a fact on screen in the first ten seconds. One risk to manage: a "look what's missing" open is a negative-space reveal, harder to read on video than something visibly working. If it feels slow in a test cut, lead with a 3–4s cold tease of the product working (skeleton overlay, USDC ticking up) then land the threshold reveal — earn the attention, then make the point.

06 Narration script

Phase 7 — exact words, timed to the beats above. Read it like you're explaining your own code to another engineer, not pitching a room.

0:00Network tab — bounty API
"This is a bounty on World Mod. It pays sixty cents in USDC for a fifteen-second recording of someone typing at a keyboard — if the recording passes." "Here's the API response for that bounty. Look for the acceptance threshold. It's not here. It's not on the page either. It's not even in the message you get when you're rejected."
Why: the differentiator has to be the first thing on screen, as a fact, not a claim.
0:18Context beat
"Right now, if you want to get paid for AI training data, you've got two options. An academic program flies out hardware you can't buy to a few hundred people. Or a gig platform pays you through a backend that — as of last year — is being sued for unpaid wages and deactivating workers with no explanation." "Neither of those is a blockchain problem. They're a trust problem. So we built the version where the thing deciding if you got paid can't be quietly changed by whoever runs the platform — including us."
0:45World App — capture
"This is World Mod running as a World App mini app. First time, every contributor does a Selfie Check — a real one, against World's production verification API, not a mock. It's good for ninety days, then it's out of the way for good." "Now I record. The phone only ever draws a skeleton overlay — it used to score the take on-device, and that cost us frame rate on the footage we're actually trying to sell. So scoring moved server-side, from the actual bytes."
1:35Result screen
"Accepted. Sixty cents, USDC, real testnet money, released the moment the server re-verified the bytes I uploaded — hand framing, and motion against the phone's own gyroscope, checked against a real measured anti-spoof number, not a guess."
1:55Terminal — CRE simulate
"Here's how that pass-or-fail bar actually gets checked. This is a real Chainlink CRE Confidential Workflow, running right now. It fetches the buyer's threshold as a secret, inside a TEE — an actual enclave, not our server." "It just rejected this episode. Watch the log: it never made an on-chain call. Not 'wrote a rejection' — made zero call at all. The absence of that transaction is the rejection."
2:20.env → re-run
"I'm changing one line — the buyer's secret threshold — and running the exact same episode again." "Same code. Same recording. Different secret — and now it passes: the workflow writes the verdict to this deployed contract on Sepolia. To be clear, Chainlink's already granted us live-deploy access; this is the CLI simulation on purpose — the exact same enclave code path a live deploy runs. Contract, redaction, reject-versus-accept branch, all real and here to check."
Deploy access is genuinely granted — verified via cre account access. Simulating anyway is a choice, not a workaround, so say it that way rather than apologizing for it.
2:50HashScan
"Same principle, second chain: this bond was issued on Hedera's Asset Tokenization Studio, backed by episodes that passed this exact validation. Real transaction, real Sourcify-verified contract, right there on HashScan."
3:00Closing
"We didn't add a blockchain to a data-labeling app. We took the one thing that made the last version of this idea fail people — an operator who could quietly decide who gets paid — and put it somewhere nobody can reach. Not the buyer. Not us."

09 Cut list — do not show

Phase 12 — built the feature doesn't mean the judge needs to see it.

  • The bounty-creation form in fullAdmin CRUD, not interesting to anyone but you. If buyer-side matters, show the result (an escrowed bounty), not the form.
  • The live world-model prediction panel, lingered onReal, but trained on 5 episodes and doesn't beat its own baseline yet. A one-second flash at most — dwelling on it undercuts confidence in everything else.
  • The standalone landing siteDeployment status unconfirmed. Don't put an unverified asset in a judged video.
  • Full test-suite output scrolling byA "107/107" badge earns more credibility per second than a terminal scroll nobody's reading.
  • IDKit/MiniKit SDK internals or codeShow Selfie Check working on the phone. The judge doesn't need to see the hook usage.
  • Any moment presented as "the DON broadcast a live transaction"It didn't happen — deploy access is granted, but this is the CLI simulation on purpose. Say "simulated, by choice, same code path" every time, not "pending."

10 Judge simulation

Phase 11 — brutally honest, not the highlight reel.

What lands

  • The redacted-threshold fact — verifiable on screen, not a slide claim
  • A real, measured anti-spoof accuracy table most hackathon demos never bother publishing
  • Money actually moves, on two chains, with tx hashes a judge can click
  • Being upfront that deploy access is already granted and simulation is a deliberate choice — not a blocked feature — reads as confident, not defensive

What to watch for

  • Three sponsor tracks (Hedera, World ID, Chainlink) can read as bounty-chasing if not narrated as one story — the script above deliberately threads them through a single trust argument
  • A judge who reads the repo will find "no workflows deployed yet" in cre workflow list regardless — own the "we chose to simulate, access is granted" framing on camera before they find the gap themselves
  • The world-model feature, if shown at length, invites "so it doesn't actually work" — keep it to a flash or cut it entirely
  • Landing site exists in code with no confirmed deploy — don't reference it as if it's live

What would make this stronger: deploy access is already granted, so a real live DON deploy turning the pass-path into an actual Sepolia transaction is genuinely one funded mainnet wallet away — not gated on anyone's approval anymore. Also worth closing: a second live recording that clears the confidential bar on camera, so a real accept is shown through the same CRE path, not just the app's own off-chain scorer.

Built from a direct inspection of the running repository — every real/simulated/mocked label above traces to a file, a test run, or a transaction hash, not a README's word for it. Nothing here was invented to make the story work.
